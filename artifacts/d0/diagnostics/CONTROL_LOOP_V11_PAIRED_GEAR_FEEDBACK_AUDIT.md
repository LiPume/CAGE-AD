## 为什么还要核验一次

V10 已消除“CARLA 实际为 0 挡、bridge 却回报前进挡”的假象，也没有让闭环退化。但是外部采集器把不同线程的最新消息放到同一行，在自动变速箱从 0 挡切到 1 挡时，出现 1 帧“上一条 Apollo 空挡消息 + 稍后的 CARLA 1 挡状态”。

这轮不再用异步拼接结果裁决修复。bridge 在构造底盘消息的同一段代码里，读取一次 CARLA 状态，并把“读取到的真实挡位”和“本次实际发布的 Apollo 挡位”成对写入同一条记录。

## 唯一允许的修改

- 给已有诊断日志增加记录类型；
- 每次发布 Apollo 底盘消息时，成对记录 CARLA 实际挡位、自动/手动挡状态和已发布挡位；
- 增加离线汇总工具和 CPU 测试。

不允许修改控制命令、挡位映射、油门、刹车、转向、加速度滤波、车辆物理、场景和数据协议。

## 通过条件

1. CPU 测试确认日志中的两侧值来自同一次 `send_vehicle_msgs` 调用；
2. 唯一一次 20 秒运行中，每条成对记录都符合 V10 冻结映射，错误数必须为 0；
3. 必须同时观察到真实 0 挡和 1 挡，自动挡始终开启；
4. 400 帧完整，无跳帧；规划覆盖率至少 95%，速度优化器失败 0 次，横向偏离不超过 0.20 米，前进至少 5.714 米；
5. 外部逐帧拼接仍单独报告，但不再用它代替同时刻证据。

本轮预算 10 分钟开机时间、256 MiB 新增文件。仍是控制闭环诊断，不是数据集，不运行正式 TTC。
