# V18 单场景交互测试：近距离前车刹停

状态：**已完成并按合同停止审计；TTC 已不再全空，但场景未进入规定敏感区；正式数据集继续暂停**

## 这次只验证什么

只运行一次 `lead_brake_close / LBC0 / seed 1101`，总时长固定为 32 秒。通俗地说：自车按 Apollo 行驶，前方一辆车先行驶，6 秒时开始减速并停下。我们检查前车是不是真的执行了动作、自车是不是真的追近，以及 TTC（按当前运动趋势预计还有多久接近到车辆外框相碰）是否终于出现有效数字。

这不是正式数据样本，不进入训练、测试或论文指标，也不更改场景、标签、切分、故障、预算或 TTC 算法。

## 固定输入

- 车型仍为 `vehicle.lincoln.mkz_2017`，不换特斯拉；
- 使用 V17 已通过无车测试的表，SHA256 固定为 `2693818651d7799eac5f206b88af0c0fb86f38b34443c1b14b4ccd45ffe482aa`；
- 场景 `lead_brake_close`，候选 `LBC0`，seed `1101`；
- 32 秒、预计 640 帧；
- 只允许本次隔离运行，不批量运行，不重试第二遍来挑结果。

## 运行前冻结的通过条件

1. 程序正常完成，恰有一辆自车和一辆交互车，640 帧且不跳帧；
2. 前车出生位置误差不超过 0.10 米，朝向误差不超过 1 度，速度执行误差不超过 0.25 m/s，动作开始时间误差不超过 0.15 秒，并观察到前车停下；
3. 冲突开始前 3～6 秒自车速度中位数至少 1.8 m/s，避免把“自车还没开起来”误判成场景成功；
4. 两车最小外框距离小于初始距离，且确实有持续接近；
5. 主计算和独立复核的 TTC 都至少出现一次有效数字，不能全为空；
6. 主计算与独立复核不能连续出现“一个有值、一个为空”的稳定分歧；
7. 主 TTC 至少一次进入 `(2.5, 6.0]` 秒范围，证明场景形成了有诊断价值但不是只在最后一瞬才出现的接近；
8. 运行清单必须证明实际加载的就是固定 V17 表。

任何一项失败，结论都是 `STOP_AND_AUDIT`，不生成数据集。尤其如果 TTC 全为空，本次之后立即停下检查，不连续重跑。

预算上限：300 秒开机时间、256 MiB 新增文件。

## 测试结果

唯一一次运行是 `V18_LBC0_SEED1101_32S`，执行源码提交为
`6906a3a71c5c7e49012d3579caa31e990857eb91`。运行正常结束，640 帧连续无跳帧，实际开机
86.4775 秒，只有一辆自车和一辆交互车。CARLA、bridge 和 Apollo 在结束后均已关闭。

最重要的好消息是：**TTC 不再全为空。** 主计算得到 72 帧有效 TTC，独立复核也得到 72 帧；两者没有一帧
出现“一个有值、另一个为空”的分歧。第一帧有效 TTC 出现在 21.40 秒，主计算为 10.0 秒；本次最小值是
7.30 秒，主计算和独立复核都为 7.30 秒。由此可以排除“当前几何关系永远算不出 TTC”这一旧问题。

场景动作也真实发生了：前车出生位置误差仅 0.000015 米、朝向误差为 0，速度执行均方根误差为
0.1266 m/s；前车约 7.60 秒停下。冲突前 3～6 秒的自车速度中位数为 2.0572 m/s，因此这次不是自车完全
没开起来。两车外框距离从 25.6935 米缩小到 11.2635 米，累计正向接近 23.65 秒。

## 为什么仍然没有通过

冻结条件要求主 TTC 至少一次进入 `(2.5, 6.0]` 秒，但本次最低只有 7.30 秒，所以正式结果必须是
`STOP_AND_AUDIT`。自车约在 23.75 秒后从 1.73 m/s 很快刹到接近 0，随后又起步；约 28 秒和 31 秒附近
再次发生类似过程。车一停，闭合速度接近 0，TTC 按定义恢复为空；再起步接近时，TTC 又恢复为有效数字。
这不是 TTC 丢失，而是车辆真实运动状态改变。

这一“猛刹—再起步”与 V3 的 CARLA-only 证据一致：Lincoln 在约 2 m/s 下，即使很小的正刹车输入也会
极快停车。V17 只修了正加速度一侧，并明确没有修改负加速度标定，因此当前最小证据指向低速制动链仍不匹配。
在把这一点量清楚前，不应直接批量试 5 个 seed，也不应通过缩短车距来掩盖制动执行问题。

另有两个审计细节如实保留：

- 前车动作检测值为 `0.1500000916` 秒，按源码逐字比较略高于 0.15 秒，故该项仍记失败；它对应 0.05 秒
  仿真步长上的 6.15 秒检测帧，不是前车没有动作。
- 第一版离线评估器把清单中的文件相对路径少写了 `apollo_conf/`，错误地报告“控制表未绑定”。原始错误
  评估文件未删除；修正后的评估源码提交为 `a70d491d1a409d34e266a65d065a447b829e7b31`，修正结果证明
  运行清单、复制文件与冻结 SHA 完全一致。该修正没有改变 TTC 门槛，最终结果仍为 `STOP_AND_AUDIT`。

## 结论和下一项最小检查

V18 证明了三件事：自车现在能稳定达到约 2 m/s；前车程序真实执行；TTC 可以稳定产生并被独立复核。
所以“全部 TTC 为空”的根因已经解除。它同时证明 LBC0 在当前低速制动执行下未进入协议要求的敏感区，不能
进入数据生成。

下一项最小检查不是立刻重复 LBC0 或批量换 seed，而是只开 CARLA，把 2 m/s 下更细的微小刹车输入量清楚，
确认 bridge 所需的低速刹车范围是否存在。如果 CARLA 在更小输入下仍然近乎开关量，就停止用 Apollo 标定表
掩盖车辆物理；如果存在可重复的渐进区间，才预登记负加速度标定候选。整个过程不改场景、标签、split 或 TTC。
