# Apollo—bridge—CARLA 控制闭环 v7 修复计划与结果

V6 已固定可用的 `RenderOffScreen → load_world(Town01) → bridge` 顺序和转向 `0.419643`。本轮只验证加速度反馈，数据集和 TTC 继续暂停。

## 唯一修改

把 `localization_accel_alpha` 从 `0.0` 改为预先选定的 `0.15`。20 Hz 下等效时间常数约 `0.31 s`；V2 原始序列离线重放范围约 `[-0.60, 1.73] m/s²`，位于 Apollo 车辆边界 `[-6, 2]` 内。

油门 `1.5`、刹车 `1.0`、转向 `0.419643`、车辆、路线、时步、规划源码和所有评价标准不变。只运行一次 20 秒无车闭环。

## 冻结门槛

- Apollo 收到的前向加速度不能全为零；
- 反馈范围必须在 `[-6, 2] m/s²`；
- 速度优化失败次数必须保持 0；
- 横向范围不超过 `0.20 m`；
- 有效规划覆盖不得低于 V6-B 的 `0.9775`；
- 位移不得低于 V6-B 的 `13.56077 m`。

任一失败就把 alpha 回滚为 `0.0`，保留 V6 的启动和转向修复，不试第二个 alpha。成功才允许评估最终 70% 速度比是否恢复；无论结果如何都不修改门槛。

V7 预算 15 分钟、512 MiB。

## 测试后结果

`NO_NPC_V7_ACCEL_01` 完成一次完整 20 秒闭环。冻结门槛全部通过：

- Apollo 前向加速度 400 帧中有 390 帧非零，范围 `[-0.17750, 1.76916] m/s²`，位于 `[-6, 2]` 内；
- 速度优化失败 0 次；
- 横向范围 `0.02036 m`，低于 `0.20 m`；
- 有效规划覆盖 `0.9775`，没有低于 V6-B；
- 位移 `14.98069 m`，高于 V6-B 的 `13.56077 m`；
- 无断帧、无其他车辆、挡位一致、路线成功、运行正常退出。

因此 `localization_accel_alpha=0.15` 保留，不回滚。

最终 70% 速度跟踪门槛仍失败，但实际/计划速度比从 V6-B 的 `0.5197` 提高到 `0.5584`；实际中位速度约 `0.888 m/s`，计划约 `1.590 m/s`。这只能表述为改善，不能写成最终通过。

剩余问题已缩小到纵向车辆标定/油门映射。下一阶段不能复用 V2 的单一油门倍数，必须先取得多档开环响应并建立车辆专用映射；数据集和 TTC 继续暂停。
